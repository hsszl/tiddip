# 手机筛选

直接打开 `index.html`；不需要安装依赖、构建或启动服务器。线上地址为 `https://tiddip.com/phones/`，由仓库的 GitHub Pages 工作流发布。

## 页面

- 所有品牌混排，品牌可多选；搜索型号、芯片和原始参数文字。
- “只看有报价”按同一配置的本期统计价筛选；默认关闭，取消或重置后保留全部机型的参数。
- 默认显示价格、GB6 多核、重量、电池、屏幕、有线充电 6 组双端滑块；“更多参数”展开其余控件。
- 共 23 个数值范围：价格、GB6 单/多核、GB7 单/多核、安兔兔、重量、厚度、屏幕尺寸/刷新率、电池、有线/无线功率、内存/存储、主摄/长焦/超广角/前摄像素、持续/瞬时触控、蓝牙版本、CPU 最高频率。
- 8 个分类条件：芯片、分辨率、屏幕形态、防护、内存类型、闪存类型、USB、发布年份。数值字段均支持排序，另有名称和发布时间排序。
- 横条显示最近统计价及独立的括号预估参考值；GB6 单/多核分数紧接芯片名称，屏幕英寸与“小屏 / 中屏 / 大屏”默认直接可见。点击展开其他参数及“预估依据”，不增加上期价栏目。
- 本页尺寸分档采用屏幕对角线：小屏 ≤ 6.4 英寸，中屏 > 6.4 且 < 6.7 英寸，大屏 ≥ 6.7 英寸；这是本页显示规则，不是行业标准。折叠机的内外屏分别标注，默认屏幕滑块下也直接显示分档刻度。

## 数据来源与开源状态

2026-11-14 检查 `https://mingqimiao.cn/` 公开页面、页面链接和相关检索，未发现其公开源代码仓库或开源许可证。本站为独立编写的前端，不是对原站代码的开源 fork，也没有修改原站。

参数采用该页公开嵌入的 `PHONES` JSON，日期来自 `DATES` 和页脚；保留全部原始记录和字段。当前快照为 160 款、12 个品牌，原站标注更新至 **2026-11-11**。`data.js` 内记录采集时间、来源及源页面 SHA-256。缩略图直接引用原站公开图片；断网或图片失败时显示品牌首字，不阻断筛选。

上游描述为《手机参数对比汇总表》及公开跑分资料。具体跑分来源采用记录自带的 `gbUrl`，其中有 NanoReview 页面，不能一概称为直接来自 Geekbench 官网。没有找到原始表格的独立下载地址，因此刷新以原站公开网页为准。

没有可靠来源的宽度、系统、SIM、二手等数据不随意填值；系统与SIM仅补有明确资料的条目，不建立虚假的筛选项。原站数据和图片不因本项目独立编写而取得新的授权，其授权应与页面代码分开处理。

### 缺价核对

2026-11-15 重新抓取原站并与本地数据逐条比较，160 条记录及价格批次一致；原站运行后的数据也没有动态补价。其中 50 款仅有参数，价格、配置、配置历史均为空，因此显示“未收录报价”。其余机型也可能有本期未报价或无货的配置。

“只看有报价”仅保留有本期有效报价的配置，不把补缺估值计作实际报价。掌中参数库（`https://www.phonepara.cn/phones`）及其 ZOL 详情主要提供参考标价／起售价，缺少逐条现价日期；新增补值不会写入原统计价。

### 批量补缺

2026-11-15 批量核对掌中参数库/ZOL、芯片与手机厂商资料、极客湾、安兔兔及同芯片原表样本；边角缺价再查具体型号的官网与上市报道。原先完全缺少配置/报价的50款均有独立价格参考；本轮实际展示99个价格参考及626个参数/配置补值，仍有758个数值缺项没有可靠依据。每个数值字段的覆盖与剩余缺口见 `supplements.js` 的 `meta.numericCoverage`，并非所有空缺均已填满。

- 新补内容统一以 **“（预估…）”** 标出：包含有来源的规格参考和明确方法的计算值。每台“预估依据”保留来源、口径、样本ID或方法；不覆盖原有非空值。
- 参考标价同时显式标 **“参考标价，非现价”**；页面活动价标明未验结算；历史价格标“历史推估”；无同型号价格时才采用相关机型中位数，标“同类推估，配置待核”。价格按50元取整，不把同品牌旗舰折扣套到其他定位的机型，也不制造不存在的出厂配置或现货。
- 所有补值只用于展示，**不写入用于筛选/排序的 `metrics` 或 `offers`**。拖动任何滑块仍保留原始缺失值；括号数值即使超出区间也不会因此被排除。“只看有报价”仍仅认原表有效报价。
- 同芯片分数只按相同主版本推估；极客湾峰值上沿额外标“峰值参考”。安兔兔补源保留 Android V12 / iOS V11 等版本信息，不混成统一实测分。官方Geekbench总榜与部分设备详情版本标注冲突的候选值未采用。
- **未全部补满所有参数。** 无明确资料的触控、无线充电、镜头、部分跑分等继续未知；没写功能不等于不支持。无货不会生成在售价格，二手价和评分没有统一条件/口径时不造数字。`unresolved` 与 `rejected` 分别记录未解决项和拒收项。
- 完整原文缓存不发布；仓库仅保存补缺事实、必要依据及来源链接。不同来源已有值冲突不自动覆盖原表；例如A6s Pro官方芯片名称与原表不一致，在对应CPU补值里注明。

## 数据规则

- 价格、运行内存、存储必须由**同一配置**同时满足；筛选后横条只显示符合的配置，价格排序也基于这些配置。
- 原报价按每个配置最新记录显示，保留批次日期；该期缺失或无货不回填为真实报价。历史记录可作为另行标注的估值依据，不显示为额外价格栏目。
- 缺失不是 0：拖动价格、内存、容量、性能、重量等滑块时，缺失值仍保留；只排除有明确数据且超出范围的配置或机型。没有配置资料的机型也保留，不猜填价格或容量。只有主动勾选“只看有报价”才按报价存在与否排除。正序、倒序都将缺失排序值放末尾。
- 重量、厚度按原文中的单位解析，并采用最重/最厚值；原文完整保留。折叠机的闭合厚度可能混在原站重量字段中，联合解析两字段的 `g` 和 `mm`，避免串单位或只使用展开厚度。
- GB6 / GB7 分开；安兔兔保持原表数值，原表没给版本，不做跨平台或跨版本综合评分。
- 无线功率、摄像头、USB 等仅从明确标注解析；未提到无线充电不推断为不支持。复杂原文不确定时保留原文、数值留空。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `index.html`、`style.css` | 极简筛选栏和横条布局 |
| `app.js` | 双端滑块、品牌、排序、详情及 DOM 渲染 |
| `model.js` | 单位解析、配置报价、筛选与排序，无 DOM 依赖 |
| `data.js` | 可离线加载的真实数据快照，不执行上游 JavaScript |
| `supplement-evidence.json` | 精简的补缺输入事实、来源、日期和推导方法 |
| `supplements.js` | 生成的展示补值、覆盖统计及未解决清单，与原数据独立 |
| `scripts/build_supplements.py` | 校验字段/单位、计算补缺参考，拒收来源或单位不明的数据 |
| `scripts/update_data.py` | 手动刷新快照，标准库实现 |
| `tests/` | Node 原生测试、Python 单元测试 |

`index.html` 的样式和界面脚本 URL 带内容哈希。修改这些文件后同步更新哈希，避免桌面预览只刷新 HTML、仍执行缓存的旧脚本；发布前读回预览中的实际横条确认。

## 手动更新

在仓库根目录执行：

```bash
python -B phones/scripts/update_data.py
```

若普通 HTTP 访问失败，可在浏览器保存原站 HTML 后：

```bash
python -B phones/scripts/update_data.py --source-html "保存的原站.html"
```

更新器只读取 JSON 常量，不执行网页脚本；空数据、重复 ID 或缺少标记会报错，旧快照保持不变。没有设置定时任务。

补缺输入核实更新后执行 `python -B phones/scripts/build_supplements.py`，默认读取仓库内 `supplement-evidence.json`。也可用 `--evidence 文件1.json 文件2.json` 显式提供新的采集结果。脚本只重建补值，不重新联网、不改原表；原表刷新后也应重建，以免继续展示已有新真值的旧补值。重建后同步更新 `index.html` 的资源哈希。
