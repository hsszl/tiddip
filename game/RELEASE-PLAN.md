# 上线准备

目标：每回合 30 秒、限制匿名房间占用、明确动作高亮，并让当前单进程服务具备可部署的入口和可选持久化。保持原生 Node.js、客户端/服务端分离，不新增第三方依赖。

- [x] 服务端保存回合截止时间；读取、动作和后台时钟均检查超时，迟到请求不能生效。地雷超时自动选合法已揭示落点，无合法落点则留在原格并结束回合。
- [x] 每来源最多保留三个房间，来源不随房主转移改变；只读轮询不延长寿命。大厅 15 分钟、选出生点 10 分钟、游戏 30 分钟无人工操作、结束后 10 分钟回收，房间绝对寿命六小时。
- [x] 请求来源默认仅取连接地址；可显式配置受信代理，校验并从右向左解析转发链。已认证玩家独立限流，防止代理下所有玩家共用读额度。
- [x] 客户端显示小型倒计时；攻击范围只在攻击模式或悬停攻击按钮时显示，已使用的动作不再显示范围。
- [x] 可选私有目录原子保存房间及截止时间，重启恢复；目录进程锁阻止多个工作进程各自维护一份状态。提供 Passenger CommonJS 启动入口、容器配置和上线说明；不实际发布。
- [x] 只做定时、配额、代理与存储边界的针对性检查，浏览器确认倒计时/高亮；分批 Git 提交。

需重点核对：截止时间前后的请求、地雷连续触发、掉线/只读房间回收、代理身份伪造、重启后的私有手牌与截止时间。IP 配额不能防分布式攻击；正式部署必须单进程、HTTPS、私有可写持久目录。

验证记录：相关 16 项检查通过；随后增加跨 PID 命名空间锁保护，三项存储检查通过。JS 语法与 diff 格式检查通过。浏览器实测 30 秒自动换轮，默认射程覆盖透明无边框，选择攻击时显示。真实 app.cjs 服务重启后，通过 HTTP 确认同一房间、本人手牌与截止时间恢复，其他人手牌仍隐藏。容器与真实 Passenger 环境尚未运行验证。IPv6 按 /64 合并匿名配额；异常锁跨主机或命名空间恢复需先停掉所有实例，见 DEPLOY.md。
