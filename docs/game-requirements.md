# 迷雾地图卡牌对战游戏：需求草案

状态：已进入可玩 Demo。下文保留最初需求草案；后续已确认规则与临时实现配置以 `../gaogame/docs/DESIGN.md` 和 `../gaogame/docs/CHECKLIST.md` 为准。

本文件记录用户已提出的规则；未明确的数值、交互和胜负条件统一标为“待确认”，不作为已定规则。

## 1. 游戏概念

将原本的卡牌游戏改造成一个二维、多人、回合制的迷雾地图对战游戏。

- 一局有 n 名玩家。
- 玩家在一定大小、由四边形地图块组成的地图上移动和战斗。
- 地图块初始被迷雾覆盖，玩家进入后揭示地图块。
- 武器牌决定玩家的血量、攻击距离，并可能提供技能。
- 道具牌和地图块效果影响战斗与探索。

暂不制作三维版本。玩家人数范围、地图大小、四边形是否统一为正方形，均待确认。

## 2. 本阶段交付范围

本阶段只整理需求，不编写游戏代码、不搭建服务、不安装依赖、不部署。

后续首先实现最基础的二维玩法。联机方式、界面布局和详细技术方案在规则明确后再确定。

## 3. 开局流程

已提出的流程：

1. 生成地图，所有地图块初始处于迷雾中。
2. 每名玩家抽取 1 张武器牌和 3 张道具牌。
3. 玩家自主选择地图块，作为自己的出生位置。
4. 揭示出生位置的地图块。
5. 向所有玩家公布每名玩家的武器牌。
6. 进入回合流程。

待确认：

- 玩家选择出生位置的顺序，以及是否可以选择同一个地图块。
- 所有地图块是否都允许作为出生位置。
- 出生时揭示地图块，是否同时触发该块效果，例如地雷伤害。
- 武器决定的血量是否在开局直接设为满血。
- 道具手牌是否仅持有者可见。
- 玩家行动顺序如何决定。

## 4. 玩家与生命值

- 每名玩家持有 1 张初始武器牌、3 张初始道具牌。
- 武器具有血量属性，目前设想包含 3、4、5 点血量。
- 生命值使用 Minecraft 风格的红心表示。
- 所有武器的攻击伤害统一为 1 点。
- 地图和道具也可能造成伤害或恢复生命。

待确认：武器血量是否就是玩家最大生命值、回血上限、零血后的处理、是否存在复活，以及中途能否更换武器。

## 5. 地图与迷雾

### 5.1 地图结构

- 地图有固定的一定大小，由四边形地图块组成。
- 地图块有不同类型，不同类型具有独特效果。
- 玩家位置以地图块为单位表示。
- 普通地图块的同格人数上限待确认；规则中存在针对同格玩家的攻击技能，因此系统需要支持同格交互。

### 5.2 揭示规则

- 所有地图块初始有迷雾。
- 开局揭示玩家出生位置。
- 玩家移动到某块后，揭示该块。

待确认：

- 揭示结果对所有玩家共享，还是只有进入者知道。
- 已揭示地图块是否永久可见，或者离开后重新出现迷雾。
- 玩家能否看见迷雾中的其他玩家。
- 迷雾隐藏的是地图类型、玩家位置、地图效果，还是它们的组合。
- 是否能直接看见邻近地图块；目前只确定出生和进入可以揭示。
- 地图类型如何分布：随机生成、固定地图，或其他方式。

## 6. 回合与行动

每名玩家在自己的回合中可以选择移动和攻击：

- 可以先移动再攻击，也可以先攻击再移动。
- 可以选择不移动。
- 可以选择不攻击。
- 攻击目标由玩家选择，但必须满足最终确定的攻击规则。

“无论对象”的具体含义尚未明确，不据此默认允许攻击自己、攻击任意距离的目标或一次攻击多个目标。

待确认：

- 每回合移动和攻击的次数，是否各最多一次。
- 每次移动的格数、允许的方向，是否可以斜走。
- 是否可以跨越地图块；跨越时哪些块需要揭示或触发效果。
- 能否原地移动，以及移动是否允许撤销。
- 技能和道具能在什么时机使用，是否占用移动或攻击次数。
- 是否有行动时间限制，以及不操作时如何结束回合。
- 同一回合攻击前后是否可以切换不同目标，是否允许攻击自己。

## 7. 武器牌与攻击

### 7.1 武器属性

每张武器牌需要表达以下信息：

| 属性 | 已知需求 |
| --- | --- |
| 名称 | 区分不同武器 |
| 血量 | 例如 3、4、5 点 |
| 攻击距离 | 武器的关键属性，决定能攻击哪些位置 |
| 伤害 | 所有武器统一为 1 点 |
| 技能 | 可以有，也可以没有 |
| 技能剩余次数 | 对有限次数的技能进行记录 |

### 7.2 示例武器：狙击枪

- 血量：5 点。
- 普通攻击：可以攻击直线“2/3 格”的目标。
- 技能：有一次机会，在距离为 0（双方位于同一地图块）时，对对方造成伤害。
- 按所有武器统一伤害的设定，该技能伤害暂记为 1 点；是否存在技能例外待确认。

“直线 2/3 格”的含义待确认：仅第 2、3 格可以攻击，还是射程上限为 2 或 3 格的不同版本，或其他定义。

### 7.3 攻击判定待确认

- 直线是否仅指横向和纵向，是否包含对角线。
- 普通攻击能否攻击同格目标，还是仅特定技能允许。
- 迷雾是否阻挡攻击或目标选择。
- 地形或其他玩家是否阻挡射线。
- 是否只能攻击可见目标。
- 同格有多个目标时，攻击如何选择和结算。
- 技能的一次使用机会，是每局一次还是其他周期。

## 8. 道具牌

- 开局每名玩家抽 3 张道具牌。
- 道具牌有不同类型。
- 已提出的类型：回血道具。

待确认：回血量、使用对象、使用时机、能否超过最大生命值、使用后是否弃牌、后续抽牌方式、手牌上限，以及其他道具种类。

## 9. 地图块类型

| 地图块 | 已确定效果 | 待确认事项 |
| --- | --- | --- |
| 厕所 | 同一时刻只能有 1 名玩家在里面 | 是否允许作为出生点；满员时如何处理移动；是否有保护、回血等额外效果 |
| 地雷区 | 触发后损失 1 点血，并被炸飞到一个可以指定的地图块 | 谁指定落点；允许落点的范围与限制；触发次数；零血时是否仍被炸飞 |
| 其他类型 | 不同地图块有各自效果 | 完整类型清单与具体效果 |

地雷还需明确：

- 被炸飞后，是否揭示落点、是否触发落点效果。
- 落点为已满员厕所时如何处理。
- 落点仍是地雷时，是否发生连续触发。
- 强制位移是否消耗本回合移动机会。
- 回到已揭示的地雷区时，是否再次触发。

不默认厕所附带保护效果，也不默认地雷为一次性机关。

## 10. 图片与视觉占位

- 首版图片资源暂用 Minecraft 缺失贴图风格的黑紫棋盘格占位。
- 武器、道具和地图块的图片均可采用这一占位方式。
- 占位图旁仍需显示名称或文字说明，避免所有资源外观相同而无法辨认。
- 血量采用 Minecraft 风格的红心。
- 首先保证二维地图、玩家位置、迷雾和行动状态容易辨认。

后续可自行绘制黑紫占位图和像素红心，不要求下载 Minecraft 游戏原始资源。正式美术和动画不作为首版前提。

## 11. 多人与服务端

- 一局包含多名玩家，采用回合制。
- 此前已表达游戏需要服务端，后续技术方向倾向 JavaScript + Node.js。
- 服务端应负责验证行动并结算权威游戏状态，例如位置、生命值、手牌、技能次数和回合顺序。
- 若迷雾或手牌包含玩家私有信息，服务端需要按玩家权限返回可见信息。

待确认：首个可玩版本是否直接支持在线联机，还是先在同一台设备上验证规则；房间、加入方式、断线处理、存档和重新开局需求也待确定。

具体通信方式、数据库和部署平台尚未确定，不默认现有 Supreme 共享主机能满足最终联机运行需求。

## 12. 胜负与异常情况

以下是形成完整游戏循环前必须补齐的规则：

- 胜利条件：最后一名存活者、积分目标、组队胜利，或其他方式。
- 零血处理：立即淘汰、倒地、复活，或其他方式。
- 是否有队伍，以及能否攻击队友。
- 地图无合法移动位置、强制位移无合法落点时如何结算。
- 多名玩家同时满足胜利或淘汰条件时如何处理。
- 游戏是否有回合上限或平局条件。

## 13. 后续实现的验收方向

以下用于检查基础玩法是否正确；其中依赖未定规则的项目，需要先确认规则才能形成最终验收标准。

- 能以确定的人数和地图规模开始游戏。
- 每名玩家获得 1 张武器牌、3 张道具牌。
- 能选择出生位置、揭示对应地图块，并公布所有武器牌。
- 回合中能选择移动、攻击的先后顺序，也能跳过其中任意一种行动。
- 进入新地图块后，能按规则揭示并结算该块效果。
- 攻击按武器射程、目标条件和统一伤害结算。
- 狙击枪的同格技能按确定的使用次数生效。
- 生命变化以红心正确展示。
- 厕所始终遵守最多 1 人的限制。
- 地雷伤害、指定落点和强制位移正确结算。
- 回血道具按确定规则使用与消耗。
- 能按最终确定的胜负规则结束一局。
- 如首版选择联机，所有玩家看到的公共状态一致，私有信息按规则隐藏。

## 14. 优先确认的规则

建议后续一次讨论一个问题，优先顺序如下：

1. 每回合各能移动、攻击几次，以及一次能移动几格。
2. 迷雾揭示是否共享、是否隐藏玩家位置。
3. “直线 2/3 格”的精确定义。
4. 零血与胜利条件。
5. 地雷的落点选择和连续触发规则。
6. 第一版是否直接在线联机。

以上是待确认清单，不表示这些规则已经选定。
